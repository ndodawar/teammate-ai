# T-5.05 Visual Audit: Icon Contrast and Glass Refinement

Measured on 2026-11-20 with Chromium headless (CDP), production build (`next build` + `next start`), viewport 1440x900 for the rail and 390x844 for the drawer. Every number below came from a painted screenshot pixel, not from a hex value in the source.

## 1. Where the icons live

There is exactly one glass surface that carries icons: the workspace rail (`.rail-surface` in `components/ui/app-sidebar.tsx`). It appears in three shapes:

| Shape | Where | Width |
|---|---|---|
| Expanded rail | desktop >= 1024px | 265px |
| Collapsed rail | desktop >= 1024px, toggle | 78px |
| Drawer | below 1024px, opened by the header "Menu" button | 265px |

The icons that sit on it:

| Icon | Markup | Colour source |
|---|---|---|
| Nav icons (5) | `.rail-item > svg`, `stroke="currentColor"` | inline `style.color` on the `Link`, from `--rail-muted` / `--rail-active-ink` |
| Brand mark | `.rail-mark svg` (`<Star>` from primitives) | **hardcoded Tailwind `text-accent`**, overriding `.rail-mark`'s `color` |
| Theme toggle | `.rail-theme button svg` | CSS `.rail-theme button { color: var(--rail-muted) }` |
| Collapse toggle | sibling button, sits on `.rail-surface` edge | inline `style`, `--card` face + `--ink` icon |

Nav labels and the theme label use the same colours as their icons, so label contrast and icon contrast were measured separately.

## 2. Measured contrast before the change

Stroke vs the median painted pixel inside the icon's own box (so the plate's blur, alpha, haze, and the canvas behind it are all included).

### Light mode

| Element | Ratio | Verdict |
|---|---|---|
| Nav icon, active | 4.70:1 | pass |
| Nav icon, inactive | **3.86:1** | below the 4.5 text bar it shares with its label |
| Nav label, inactive | **3.97:1** | **fails WCAG AA text** |
| Brand mark icon | **1.22:1** | **fails the 3:1 non-text bar badly** |
| Theme toggle icon | 8.55:1 | pass |
| Collapse toggle | 16.71:1 | pass |

### Dark mode

| Element | Ratio | Verdict |
|---|---|---|
| Nav icon, inactive | 6.70:1 | pass |
| Brand mark icon | **2.71:1** | **fails the 3:1 non-text bar** |
| Theme toggle icon | 10.84:1 | pass |

## 3. Root causes, in order of severity

1. **The brand mark was not using the rail's own colour token at all.** `<Star>` hardcodes `text-accent`. On the rail plate, which is deliberately dark in both themes, azure on a mid-grey tile is 1.22:1. No amount of plate tuning fixes this: the icon has to inherit the surface's foreground token. This is the single worst defect and it is a *wiring* bug, not a taste problem.

2. **Inactive nav colour was tuned for text, then reused for the icon and the label together, and it landed in the gap between the two bars.** `--rail-muted` (#d3dbe9) over the light plate composites to 3.86:1 against the plate. That clears the 3:1 non-text bar, so the icon was technically legal, but the *label* next to it is text and needs 4.5:1: it measured 3.97:1. The two were conflated into one token, so fixing the icon alone would have left the label failing.

3. **Hover reduced contrast instead of preserving it.** The hover plate is `rgba(255,255,255,0.10)`, which *lightens* the surface under the icon. Light mode measured a drop from 3.86:1 to **3.11:1** on hover. That is backwards: the state that says "you are pointing at this" made the icon harder to read.

4. **The plate itself was near-flat, so the "glass" read as paint.** The light plate composites to `rgb(98,105,118)` at the bottom and `rgb(100,107,119)` at the top: only 2 levels of difference top to bottom, and the haze band covers just the top 38%. Dark mode is denser (`rgb(53,61,81)`), so the two themes did not share a material, they shared a gradient formula with different alpha.

## 4. What was already correct and must not regress

- Rail geometry: 265px expanded, 78px collapsed, 16px radius, drawer 265px at `translateX(0)`.
- Collapse toggle, tooltip (`.rail-item:hover ~ .rail-tip` sibling selector), active route detection, keyboard focus rings (`solid 2px`), Escape-to-close, body scroll lock, 44px drawer tap targets.
- The card face behind the collapse toggle is opaque, which is why its icon measures 16.71:1: it is not actually on the glass. Left alone.
- Theme toggle's three states and persistence.

## 5. Plan

Scope limit is five implementation files plus `docs/STATUS.md`. Chosen files:

| File | Why it must change |
|---|---|
| `app/globals.css` | every `--rail-*` token lives here, plus the plate layers and the hover/active rules |
| `components/ui/app-sidebar.tsx` | the brand mark needs to stop being a hardcoded accent; it must inherit the rail foreground |
| `components/ui/workspace-shell.tsx` | the mobile drawer trigger is the one control that opens the glass surface |

Not touched: `components/ui/primitives.tsx` (`<Star>` keeps `text-accent` for every other caller; only the rail mark overrides it, so the marketing pages do not move).

### Direction

| Step | Reason |
|---|---|
| Separate the two contrast jobs | text needs 4.5:1, icons need 3:1; one token cannot honestly serve both if it lands between them |
| Raise the icon/label colour per theme, not one shared hex | the plate luminance differs by theme, so the correct foreground differs too (PRD 12.3, DESIGN.md 2.1/2.2) |
| Make the hover plate *darken* in light mode and *lift* in dark mode | hover must never reduce legibility; the direction depends on which side of the plate the text sits |
| Widen the plate's tonal range and shift the haze to a true rim | depth that reads as glass rather than paint, without increasing alpha past the legibility budget |
| Give the active chip a touch more separation from the plate | the active row must be unmistakable at a glance, which is an identity requirement, not decoration |

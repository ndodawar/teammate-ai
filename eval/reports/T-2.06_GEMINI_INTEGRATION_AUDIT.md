## 6. Penyebab fallback (didukung bukti)

**Akar masalah tunggal:** kedua nama model di `.env.local` **tidak tersedia** bagi kunci ini
(404). Rantainya:

1. `embedTexts` memanggil `ai.models.embedContent({ model: 'text-embedding-004' })`
   (`analyze-task.ts:112,135`).
2. Provider menolak **404 "model not found"**.
3. `embedTexts` menelan error tanpa jejak (`catch { /* pending stay null */ }`, `analyze-task.ts:160-162`).
   Semua vektor `null` → `pipeline.ts:77-83` mengisi `failedPairs` untuk **setiap** pasangan.
4. `pipeline.ts:86` → `isEmbeddingFailed = true`.
5. `route.ts:85` → `isFallbackMode = true`.
6. `route.ts:88-101` → `globalAssign(isFallback:true)` + `explainAssignments(isFallback:true)`:
   **tidak ada panggilan Gemini untuk penjelasan**, K dipaksa 0, bobot fallback (S/C/M).
7. `route.ts:104` → `ai_runs` `status=fallback`.

### Pemetaan ke daftar kondisi yang diminta tugas

| Kondisi | Terjadi? | Bukti |
|---|---|---|
| API key tidak terbaca | **tidak** | key ada & `ListModels` berhasil dengan key itu |
| **Model tidak tersedia** | **YA — akar masalah** | 404 untuk `gemini-2.5-flash` dan `text-embedding-004` |
| API key tidak valid | **tidak** | `ListModels` 200, 65 model |
| Permission/konfigurasi provider | **tidak** | bukan 403; key bisa list & embed dengan model lain |
| Rate limit / quota | **tidak** (bukan penyebab saat ini) | 404, bukan 429; 503 sesekali bersifat sementara |
| Error request / response | **tidak langsung** | request berjalan; respons = 404 model |
| **Cache embedding** | **tidak** (cache kosong) | `embedding_cache` = 0 baris; cache miss → panggil provider → 404 |
| **Exception handling menyembunyikan error asli** | **YA** | `analyze-task.ts:160-162` menelan error; `ai_runs` tak simpan pesan error |

Jadi penyebab pasti: **konfigurasi model basi (404), dan error-nya disembunyikan sehingga tampak
seperti "mode fallback normal".**

## 9. AiRun & batas 3 panggilan per proses

- `MAX_GEMINI_CALLS_PER_PROCESS = 3` (`call-budget.ts:14`); `AiRun.track` **memesan slot sebelum**
  memanggil provider dan menolak panggilan ke-4 (`call-budget.ts:79-96`). Terverifikasi di
  `eval/scripts/run_ai_budget.test.ts` (panggilan ke-4 → `CallBudgetExceededError`, callCount tetap 3).
- **Cache hit tidak dihitung** sebagai panggilan: di `embedTexts`, entri cache di-`continue`
  **sebelum** masuk `pending` (`analyze-task.ts:117-127`), dan hanya `pending` yang memanggil
  `run.track` (`analyze-task.ts:143`). Jadi cache hit **tidak** memakai slot.
- Pada kondisi sekarang, embedding gagal → hanya **1** panggilan yang tercatat (embedding) lalu
  fallback; penjelasan **tidak** memanggil (mode fallback). Tidak ada risiko melewati batas 3.

## 10. Cacat observability tambahan (dua temuan sampingan)

1. **Pesan error asli hilang.** `analyze-task.ts:160-162` (`catch {}` kosong) menelan 404 sehingga
   tidak pernah sampai ke `AiRun.noteError`. Di `route.ts`, `isFallbackMode` ditentukan **sebelum**
   ada `noteError`; baris `ai_runs` `status=fallback` **tanpa** `error_message` (kolom itu juga tidak
   ada di skema — lihat `lib/ai/ai-run.ts:7-17`). Operator melihat "fallback" tanpa sebab.
   → Inilah mengapa dugaan "mungkin masalah key" muncul padahal sebenarnya **model 404**.

2. **Redaksi kunci tidak cocok format `AQ.`.** `KEY_PATTERN` / `sanitizeForLog` hanya mengenali
   `AIza…` (`call-budget.ts:158`, `ai-run.ts:84`). Kunci saat ini berformat `AQ.Ab8…` → **tidak
   diredaksi** bila muncul di pesan error. Uji: string `AQ.Ab8RANDOM…` **0 match** pola; `AIzaSy…`
   1 match. Ini risiko kebocoran kredensial ke log/baris `ai_runs` bila suatu saat error memuat key.
